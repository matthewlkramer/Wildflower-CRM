- Dates must be editable later. Historical records may remain marked date-unknown until researched, but the UI should surface that state.

2. Agenda/speaker research
- For every conference event, provide “Research agenda & speakers now.” Search the public web for the official event page, agenda/program, speaker roster, and credible organizer pages. Store research runs, source URLs, timestamps, extracted agenda/session/speaker evidence, and errors. Do not store credentials, bypass paywalls, or claim access to private attendee directories.

Do not expose keys in the browser. If no usable provider credential exists, fail visibly and retain a retryable queued request rather than fabricating results.

Automatically upsert high-confidence matched speakers as event attendees with role Speaker, confirmed status, source agenda_speaker, and citations. Ambiguous matches must go to review; never attach on name-only ambiguity.

3. Automatic timing and retroactive coverage
- Run agenda/speaker research when an event is first created (after dates/URL are available), again 21 days before start, and again 2 days before start. Use the existing scheduler/job infrastructure; jobs must be idempotent, retryable, auditable, and rescheduled when dates change. A daily sweep may enqueue due work, with unique event+research-kind+window keys and catch-up behavior for missed windows.

4. Speaker proposals

Bulk add must re-check duplicates, create minimal individual records with provenance, link to an existing matched organization when confident, not silently create organizations, then add the new person as a confirmed Speaker attendee. Make retries idempotent and audit every decision.
- Allow undo/reopen of an ignored proposal where consistent with audit patterns.
